# pg_tide v0.40.0 Implementation Plan

> **Status:** Proposed
> **Release theme:** One Real Pipeline
> **Source:** [pg-tide roadmap to focused production grade](./pg-tide-roadmap-to-focused-production-grade.md)
> **Starting point:** v0.39.0 and current `main`
> **Scope rule:** Correct and prove the native PostgreSQL outbox to NATS JetStream path. Do not add connectors or unrelated features.

---

## 1. Release Outcome

v0.40.0 is complete when this exact workflow succeeds from a clean PostgreSQL 18 installation:

1. `CREATE EXTENSION pg_tide`.
2. Create an outbox with `tide.outbox_create_if_not_exists()`.
3. Configure NATS through `tide.relay_set_outbox_v2()`.
4. Publish an event with `tide.outbox_publish()` in the same transaction as a business write.
5. Run the real relay coordinator.
6. Receive the event from NATS JetStream.
7. Observe a durable offset for the relay group, pipeline, and outbox.
8. Stop and restart the coordinator without losing committed events.
9. Replay the same event and observe the documented stable duplicate identity or JetStream deduplication.

No test-only table, direct relay catalog insert, direct outbox message insert, or simulated sink publish may be used to prove this release outcome.

## 2. Decisions to Lock Before Coding

ADR-011 must record the following decisions. Implementation must not begin until the ADR and this section agree.

### 2.1 Canonical native storage

The native pg_tide outbox is:

```text
tide.tide_outbox_messages
```

`outbox_name` is the logical stream discriminator. `outbox_create*()` creates a catalog row, not a relation. Native relay polling must use one static, parameterized query:

```sql
SELECT id, payload, headers, created_at
FROM tide.tide_outbox_messages
WHERE outbox_name = $1
  AND id > $2
ORDER BY id
LIMIT $3;
```

The global identity sequence may create gaps within one outbox. Ordering is therefore strictly increasing by `id`, not contiguous.

PostgreSQL MVCC is the visibility boundary: rows are eligible only after their publishing transaction commits. The relay must not use `READ UNCOMMITTED`, dirty-read workarounds, or notification payloads as message data.

### 2.2 Index contract

The canonical polling index is an unconditional btree index on:

```text
(outbox_name, id)
```

The existing partial index filtered by `consumed_at IS NULL` does not support the canonical query because the native relay does not filter by `consumed_at`. Retain the partial index only while legacy status and cleanup APIs still use it.

### 2.3 Native and pg_trickle paths

`source_type = "outbox"` means the native shared-table path and defaults to native/raw payload decoding.

pg_trickle compatibility must be an explicit mode, such as:

```json
{
  "source_type": "pg_trickle_outbox",
  "source": {
    "outbox": "orders"
  }
}
```

The exact JSON spelling is finalized in ADR-011. Dynamic relation access and pg_trickle claim-check tables may remain only inside this explicitly selected compatibility path. They must not be reachable from the default native path.

`tide.relay_set_outbox_v2()` defaults to the native path. If it exposes pg_trickle compatibility, it does so through one explicit optional mode value rather than storage auto-detection.

### 2.4 Offset identity and monotonicity

The authoritative native relay offset identity is:

```text
(relay_group_id, pipeline_id, outbox_name)
```

`last_change_id` is the greatest `tide.tide_outbox_messages.id` for which the sink acknowledged the complete relay batch.

Rules:

- A pipeline name reused for another outbox must not inherit the previous outbox's offset.
- A lower offset write must never replace a higher offset.
- Restart loads the exact offset matching relay group, pipeline, and outbox.
- Offset advancement occurs only after sink acknowledgment.
- Failure to persist an offset is an explicit worker error, not a warning followed by success.

### 2.5 `consumed_at` and cleanup

`consumed_at` is not authoritative native relay state. One global timestamp cannot describe independent delivery to multiple pipelines.

For v0.40.0:

- The native relay does not read or write `consumed_at`.
- Native delivery is proved through per-pipeline offsets.
- `outbox_pending`, `outbox_status().pending_messages`, and `outbox_truncate_delivered()` are documented as legacy/global-consumer surfaces, not proof that every relay pipeline delivered a row.
- Native relay documentation must not claim that successful delivery marks a message globally consumed.
- Pipeline-aware retention is deferred to v0.43.0. Until then, cleanup must remain conservative and must not infer that one pipeline's offset makes a row safe for every pipeline.

Do not add a second delivery-state table in v0.40.0. The per-pipeline offset table already provides the required state.

### 2.6 Stable duplicate identity

Preserve the existing logical forward-message identity format:

```text
outbox_<outbox_name>:<message_id>:<row_index>
```

The `outbox_` prefix is a logical compatibility identifier, not a physical relation name. NATS publishes it as `Nats-Msg-Id`. A restart or replay of the same row must generate the same value.

### 2.7 NATS subject and metadata contract

The NATS sink, not the PostgreSQL source, owns NATS subject rendering.

The v2 config must consistently accept:

- `subject` for a fixed subject; or
- `subject_template` for a rendered subject.

Keep existing documented template variables where possible and explicitly support the Quick Start's event type source. If `{event_type}` is supported, it comes from a string `event_type` header and missing or non-string values produce a documented fallback or explicit configuration error; ADR-011 must choose one behavior.

The native envelope must preserve the public outbox row data needed by the contract:

- logical outbox name;
- payload;
- headers;
- creation timestamp;
- stable deduplication key;
- source message ID.

Additive serialized fields need serde defaults so old recorded messages remain readable.

### 2.8 Fan-in disposition

Fan-in is experimental and disabled for v0.40.0.

Do not spend this release repairing fan-in unless the canonical source refactor makes it correct with a small, directly tested change. The default plan is:

- disable existing fan-in configs during the v0.40.0 migration;
- reject or skip fan-in startup with a clear experimental-feature error;
- prevent `relay_fanin_enable()` from presenting an enabled pipeline as runnable;
- label fan-in experimental in active documentation;
- retain its catalog data for a later release.

### 2.9 Upgrade compatibility

Mixed v0.39.0/v0.40.0 relay operation is not supported during the offset-key migration. The documented upgrade order is:

1. Stop v0.39.0 relays.
2. Back up the database.
3. Run `ALTER EXTENSION pg_tide UPDATE TO '0.40.0'`.
4. Deploy v0.40.0 relays.
5. Verify pipeline offsets and NATS delivery.

No automatic destructive downgrade is provided.

## 3. Current-State Gaps

These are the concrete gaps the implementation must close.

| Surface | Current state | Required v0.40.0 state |
|---|---|---|
| `pg-tide-relay/src/source/outbox.rs` | Builds `tide."<outbox_table_name>"` dynamically | Static shared-table query with `outbox_name = $1` |
| `pg-tide-relay/src/coordinator.rs` | Constructs `format!("outbox_{outbox}")` | Passes only the logical outbox name |
| Native payload mode | Public v2 config omits raw mode while native publishing writes raw JSONB | Public v2 pipelines decode native payloads by default |
| Offsets | Keyed by relay group and pipeline; simple writes can move backward | Include outbox scope and use monotonic updates |
| NATS subject | Sink stores a template but publishes `msg.subject`; documented `subject` is not authoritative | Sink renders the configured subject consistently |
| Headers | Selected public API data is not carried through the relay envelope | Headers and source metadata survive native delivery |
| `sql_to_sink_e2e.rs` | Creates a private per-outbox table, inserts relay config directly, inserts messages directly, and uses a file sink | Replaced by the public API to NATS JetStream proof |
| `nats_test.rs` | Publishes directly to NATS and calls that relay delivery | Renamed as a transport contract test or replaced by real coordinator coverage |
| `tests/common/mod.rs` | `PgTideTestDb::start()` installs only the v0.1.0 schema despite current-schema comments | Current-schema helper applies the complete migration chain; base-only setup is explicit |
| ACL handling | SPI errors in `outbox_publish_impl()` become `None`, which can allow publishing | Every ACL and role lookup error aborts publishing |
| ACL tests | Validate table DDL, not authorization behavior | Exercise real roles through `tide.outbox_publish()` |
| Fan-in | Runtime polls relation names and is presented as runnable | Disabled and labeled experimental, or fixed and runtime-tested |
| README/docs | Current examples still call removed positional relay APIs | Active examples use `relay_set_outbox_v2(JSONB)` |
| Quick Start CI | Markdown builds but SQL is not executed | Marked Quick Start SQL runs against the installed extension |
| `pg-tide-ext/src/lib.rs` | Fresh-install chain stops at v0.37.0 | Includes v0.37→0.38, v0.38→0.39, and v0.39→0.40 |
| CI schema comparison | Hard-coded migration list stops at v0.32.0 and compares two equivalent manual chains | Compares actual fresh v0.40.0 install with actual v0.39.0→v0.40.0 upgrade |

## 6. Workstream C: Native Relay Source

### C.1 Separate logical names from relation names

In `pg-tide-relay/src/source/outbox.rs`:

- rename `stream_table_name` to `outbox_name` on the native source;
- remove `outbox_table_name` from the native source and constructors;
- remove identifier validation whose only purpose was native relation interpolation;
- make `poll_simple()` issue the static canonical query;
- bind outbox name, last offset, and batch size as parameters;
- preserve payload, headers, and created timestamp when building relay messages.

In `pg-tide-relay/src/coordinator.rs`:

- stop constructing `format!("outbox_{outbox}")`;
- build the native source from the logical outbox name only;
- default public/native outbox configs to native payload decoding;
- route explicit pg_trickle compatibility configs to the isolated compatibility path.

Keep pg_trickle delta-table dynamic SQL in a clearly named compatibility-only function. Continue validating and quoting identifiers there.

### C.2 Make offset reads and writes exact

Change native offset access to include `outbox_name` in every predicate and insert.

Use a monotonic upsert:

```sql
ON CONFLICT (relay_group_id, pipeline_id, outbox_name)
DO UPDATE SET
  last_change_id = GREATEST(
    tide.relay_consumer_offsets.last_change_id,
    EXCLUDED.last_change_id
  ),
  worker_id = EXCLUDED.worker_id,
  updated_at = now();
```

After the write, confirm that the stored value is at least the acknowledged offset. Treat a zero-row write or query failure as a worker error.

Only update the in-memory `last_offset` after the database commit succeeds.

### C.3 Make acknowledgment failure visible

In `pg-tide-relay/src/coordinator.rs`, a sink success followed by an offset-write failure must:

- log an error with pipeline, relay group, outbox, and attempted offset;
- mark the pipeline unhealthy;
- retry without pretending the batch completed;
- avoid writing a success-shaped delivery receipt after the failed offset commit.

At-least-once behavior means the sink may see a duplicate in this window. Silent loss is forbidden.

Do not add the full crash failpoint matrix here; that belongs to v0.42.0.

### C.4 Native payload defaults

Update `pg-tide-ext/src/relay.rs` so `relay_set_outbox_v2()` stores an explicit native source mode. Validate that the named native outbox exists before writing the pipeline config.

Keep an explicit compatibility option for pg_trickle. Do not infer storage from the presence or absence of a physical table.

Tests:

- v2 native config produces a source the relay can decode;
- unknown outbox fails before catalog mutation;
- explicit pg_trickle mode retains v1 envelope decoding;
- unsupported mode fails with `PgTideError::InvalidArgument`.

## 8. Workstream E: ACL Fail-Closed Behavior

### E.1 Remove permissive error conversion

In `pg-tide-ext/src/outbox.rs`, replace permission-sensitive uses of:

```rust
.unwrap_or(None)
.unwrap_or(false)
.ok()
```

with `Result` propagation carrying operation and outbox context.

The critical `outbox_publish_impl()` sequence is:

1. Read outbox existence and enabled state; an SPI error aborts.
2. Query ACL existence, superuser/owner status, and role membership; an SPI error aborts.
3. Accept only explicit `no_acl`, `superuser`, extension-owner, or `allowed` verdicts.
4. Reject `denied` with the caller role and outbox name.
5. Reject unknown or null verdicts as internal authorization errors.
6. Insert the message only after authorization succeeds.

Add a dedicated `PgTideError` variant if needed so authorization-query failure is distinguishable from authorization denial.

Audit other permission-sensitive extension and relay calls touched by the native pipeline. Do not turn this into the v0.44.0 full security program.

### E.2 Authorization tests through the public API

Use a real installed extension and PostgreSQL roles. Required cases:

| Case | Expected result |
|---|---|
| No ACL entries for the outbox | Existing documented default behavior |
| Authorized publisher | Publish succeeds |
| Unauthorized publisher | Publish fails; no message row is created |
| ACL table unavailable | Publish fails; no message row is created |
| ACL query permission denied | Publish fails; no message row is created |
| Role lookup failure | Publish fails; no message row is created |
| Superuser | Publish succeeds |
| Extension owner, if distinct from superuser | Behavior matches ADR-011 and docs |

Run failure injections inside transactions and restore catalog permissions before the test exits.

Replace or rename `publisher_acl_test.rs` cases that prove only table existence or uniqueness. Those may remain schema tests but cannot satisfy the release ACL gate.

## 10. Workstream G: Authoritative Public E2E Test

### G.1 Replace the false E2E test

Replace `pg-tide-relay/tests/sql_to_sink_e2e.rs` with:

```text

```

The test name is:

```text
public_api_outbox_to_nats_e2e
```

### G.2 Environment

The test uses:

- PostgreSQL 18 with the real packaged pg_tide extension installed;
- NATS with JetStream enabled (`-js`);
- the real `Coordinator`;
- public SQL functions for outbox and pipeline setup.

Do not apply stripped SQL files as a substitute for extension installation in this test.

The local runner accepts a PostgreSQL URL from the test environment. CI installs the extension with `cargo pgrx install` into its PostgreSQL 18 instance before running the test. NATS may use testcontainers.

### G.3 Exact scenario

1. Create a clean database.
2. Execute `CREATE EXTENSION pg_tide`.
3. Create a JetStream stream matching the test subject.
4. Call `tide.outbox_create_if_not_exists('orders', ...)`.
5. Call `tide.relay_set_outbox_v2()` with a NATS sink config.
6. Start coordinator A with relay group `e2e-a`.
7. Open transaction T1.
8. Insert an order row.
9. Call `tide.outbox_publish()` with payload and headers.
10. From a second database connection, verify the uncommitted event is not visible to the relay.
11. Commit T1.
12. Receive and decode the NATS message.
13. Assert payload, headers, outbox name, source ID, and `Nats-Msg-Id`.
14. Assert the offset row is keyed by `e2e-a`, pipeline name, and `orders`.
15. Stop coordinator A cleanly.
16. Publish and commit a second business transaction while no coordinator runs.
17. Restart coordinator A.
18. Assert the second event arrives and the offset advances without losing the first.
19. Stop coordinator A.
20. Start coordinator B with relay group `e2e-b`, causing the same rows to be read from offset zero.
21. Assert JetStream deduplicates the stable `Nats-Msg-Id`, or assert duplicates expose the same documented ID if the stream's deduplication policy is intentionally disabled.
22. Shut down the coordinator and remove test resources.

Use bounded waits with diagnostics that include coordinator state, current offsets, and JetStream stream state. Avoid fixed sleeps except for short readiness backoff.

### G.4 Negative companion scenario

In the same test target or a focused companion test:

- configure a pipeline for outbox `orders`;
- publish messages to both `orders` and `payments`;
- assert the NATS stream receives only `orders`;
- assert the offset may cross global ID gaps without treating them as missing events.

### G.5 Optional proof paths

Only after the mandatory NATS test and every exit criterion pass:

- add a lightweight public API webhook test;
- add a lightweight public API PostgreSQL inbox test.

These are not release blockers for v0.40.0 and must not delay the NATS gate.

## 17. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Offset backfill cannot identify an outbox | Fail migration on ambiguity; remove only confirmed orphan pipeline offsets |
| Old relay runs after key migration | Require stop-upgrade-start and reject mixed versions in operator notes |
| Native default breaks pg_trickle users | Require explicit compatibility mode and publish migration instructions |
| NATS test is flaky | Create JetStream resources explicitly, use publish acknowledgments and bounded state-based waits |
| JetStream dedup window expires during test | Configure a deterministic dedup window longer than the test |
| Global IDs are mistaken for per-outbox sequence numbers | Test interleaved outboxes and document allowed gaps |
| `consumed_at` remains misleading | Remove it from the Quick Start delivery proof and label legacy/global semantics |
| Header/envelope additions break decoding | Use additive fields with serde defaults and round-trip fixtures |
| ACL failure injection leaves altered grants | Run in isolated databases/transactions and restore permissions in guaranteed cleanup |
| Fresh-install chain silently omits migrations | Register every migration in `lib.rs` and compare packaged fresh install to packaged upgrade |
| Documentation scan flags historical examples | Keep a small explicit allowlist with labels; active examples get no exemption |
| Scope expands into v0.42 crash testing | Test restart and visible ack failure only; defer failpoints and the full crash matrix |

## 19. Release Exit Checklist

- [ ] ADR-011 is accepted and linked from the architecture index.
- [ ] `outbox_publish()` and the relay use `tide.tide_outbox_messages`.
- [ ] Native polling uses a static query with `outbox_name`, offset, and limit parameters.
- [ ] The unconditional `(outbox_name, id)` index exists.
- [ ] Uncommitted outbox rows are not delivered.
- [ ] Native payloads from `outbox_publish()` decode without private config.
- [ ] Headers and stable message identity reach NATS.
- [ ] Offsets are scoped by relay group, pipeline, and outbox.
- [ ] Offset writes are monotonic.
- [ ] Offset commit failures are visible and retried.
- [ ] Native relay delivery does not use global `consumed_at` as authoritative state.
- [ ] NATS JetStream delivery passes through public APIs.
- [ ] Coordinator restart loses no committed event.
- [ ] Duplicate delivery is deduplicated or carries the documented stable ID.
- [ ] ACL lookup errors fail closed.
- [ ] Authorized, unauthorized, superuser/owner, missing-table, denied-query, and failed-role-lookup cases pass.
- [ ] Fan-in is disabled and labeled experimental.
- [ ] Active documentation contains no removed positional relay calls.
- [ ] Marked Quick Start SQL blocks execute in CI.
- [ ] Documentation does not hard-code historical installed versions.
- [ ] A real fresh v0.40.0 extension install passes.
- [ ] A real v0.39.0→v0.40.0 `ALTER EXTENSION` upgrade passes.
- [ ] Fresh and upgraded schemas and public smoke behavior match.
- [ ] `just fmt`, `just lint`, `just test-unit`, targeted integration tests, pgrx tests, and docs build pass.

The next roadmap version must not start until every checkbox above passes on `main`.
