# v0.57.0

> **Status:** Planned
> **Theme:** Apache Kafka inbound
> **Size:** Large
> **Depends on:** v0.56.0
> **Detailed plan:** [`plan_outbound.md`](../plan_outbound.md)

v0.57.0 adds Kafka as the second inbound source. The consumer disables
automatic offset storage and commit, tracks the highest contiguous completed
offset for every assigned topic partition, and commits next offsets only after
the PostgreSQL inbox transaction succeeds. A batch spanning several partitions
must never collapse to one scalar checkpoint.

The release owns consumer-group lifecycle as well as the happy path. Tests use
a real multi-partition KRaft cluster and cover assignment, revocation,
rebalance between relay instances, broker and coordinator outages, poison
records, stable deduplication identity, TLS and SASL, bounded backpressure,
restart, and graceful group departure. Assertions reconcile committed offsets
per partition with durable inbox event IDs.

v0.57.0 is complete when the Kafka public-API and multi-partition crash tests
are blocking under `core-kafka`, upgrade and mixed NATS/Kafka operation pass,
and connector, security, performance, runbook, and release evidence support the
source's production maturity claim.
