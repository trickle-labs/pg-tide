# v0.55.0

> **Status:** Planned
> **Theme:** Direction-aware relay foundation
> **Size:** Medium
> **Depends on:** v0.54.0
> **Detailed plan:** [`plan_outbound.md`](../plan_outbound.md)

v0.55.0 changes the relay's internal source settlement contract without adding
a public inbound connector. `Source::poll()` will return a source-owned batch
checkpoint instead of placing an outbox-only acknowledgement token on the last
`RelayMessage`. The native outbox source moves to this contract first, and all
existing forward crash-window, replay, consumer-group, DLQ, receipt, and
shutdown behavior must remain unchanged.

The release also introduces the internal direction model and closed route
validation needed by later versions. It removes hard-coded forward labels from
the worker and ownership path where that can be done without discovering or
starting reverse catalog rows. `tide.relay_set_inbox_v2()` remains unavailable,
and NATS, Kafka, and webhook remain sink-only in the public connector registry.

v0.55.0 is complete when focused source-contract tests prove
`poll -> sink commit -> acknowledge`, every failure path retains or rejects the
pending batch without advancing it, the supported forward suite passes without
changed semantics, and generated public surfaces still describe only the
v0.54.0 route matrix.
