# v0.56.0

> **Status:** Planned
> **Theme:** NATS JetStream inbound
> **Size:** Medium-large
> **Depends on:** v0.55.0
> **Detailed plan:** [`plan_outbound.md`](../plan_outbound.md)

v0.56.0 activates reverse pipelines through the retained
`tide.relay_inbox_config` catalog and restores a narrow
`tide.relay_set_inbox_v2()` API. Reverse validation accepts only a NATS
JetStream source delivering to a local or remote PostgreSQL inbox. Existing
forward documents and APIs keep their v0.54.0 behavior, and every unsupported
source-to-sink pair fails before catalog mutation or source polling.

The NATS source binds to an existing durable pull consumer with explicit
acknowledgement. It retains every fetched message handle until the inbox
transaction commits, then acknowledges the completed batch. Stable identity,
redelivery, TLS and authentication, bounded fetch, ownership handoff, and both
sides of the inbox-commit crash window receive real-service tests.

This release also closes the v0.53.0 operational performance qualification
that v0.54.0 explicitly deferred to v0.56.0. Run the eight-hour, zero-retry
qualification against the exact v0.56.0 candidate and attach its raw bundle,
comparison report, independent review, and release-manager approval to the
existing v0.53.0 evidence records. That inherited outbound qualification does
not replace the NATS inbound budget or the full bidirectional qualification
planned for v0.59.0.

v0.56.0 is complete when the public SQL-to-JetStream-to-inbox test is blocking
with zero retries, security and upgrade tests pass, the deferred v0.53.0
qualification is closed with real evidence, the source descriptor and
generated docs report supported maturity, and the NATS runbook and release
evidence prove that no source acknowledgement can precede the inbox commit.
