# v0.58.0

> **Status:** Planned
> **Theme:** HTTPS webhook inbound
> **Size:** Large
> **Depends on:** v0.57.0
> **Detailed plan:** [`plan_outbound.md`](../plan_outbound.md)

v0.58.0 adds webhook ingress as the third inbound source. One process-level
HTTP service owns the listener and route registry, while the coordinator
registers bounded request channels only for webhook pipelines owned by that
relay instance. The receiver supports direct TLS or an explicit trusted-proxy
deployment, HMAC-SHA256 authentication with replay protection, strict body and
header limits, unique normalized paths, and bounded shutdown.

Each request keeps its response channel until the PostgreSQL inbox transaction
commits. The receiver returns success for a committed insert or idempotent
duplicate and never for queue admission alone. Saturation, ownership loss,
drain, timeout, malformed identity, invalid signature, stale timestamp, and
inbox failure return bounded non-success responses that allow a sender to
retry with the same event identity.

v0.58.0 is complete when a real-network timing test proves success cannot race
ahead of inbox commit, direct-TLS and trusted-proxy security tests pass, the
public signed-request-to-inbox test is blocking, and the connector descriptor,
runbook, performance budget, and release evidence support production maturity.
